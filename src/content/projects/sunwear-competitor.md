## 客户要什么

> "我要的不是原始数据，是能向上汇报的结论。"

客户在意的是"对手做了什么、有没有打中、我们要不要跟"，不是把飞瓜千瓜的导出表再交一份回去。

## 我做了什么

**1）梳清数据源 & 权限链**

- 小红书：飞瓜 + 灵犀
- 抖音：千瓜 + 云图
- 账号权限由客户方提供，避免试用期数据缺失。

**2）周报口径标准化**

- 竞品内容按上周"数量 or 价格"从高到低排序
- 数量增长标红、下降标绿
- 大量水下笔记单独标注，不污染对比
- 案例分析必含封面截图 + 数据 + 内容形式

**3）数据 → 摘要的两阶段 AI 管线**

```
Stage 1：单竞品数据 → Python 聚合统计 → AI 提炼摘要（每个品牌独立跑）
Stage 2：所有摘要 → AI 横向竞品对比 + 策略建议
```

技术关键点：LM Studio 本地 `http://localhost:1234/v1`、Qwen3 设 `max_tokens ≥ 3500`（思考模式会先吃 token 配额）、上下文 4K 必须极度精简成 TOP5/TOP10。

## 数据穿透到结论

| 品牌 | 投放篇数 | 均点赞 | 爆款率 |
|:---|---:|---:|:---:|
| 头部对手 A | 25 | 18,043 | 56% |
| 中部对手 B | 111 | 16,330 | 0% |
| 中部对手 C | 107 | 6,035 | 0% |
| 客户主竞品 | 235 | 118 | 0% |

**主竞品篇数是头部对手的 9.4 倍，均点赞只有头部对手的 0.65%。**"量堆"策略严重低效。

## 价值

- 客户拿到的是"对手的选择是否值得跟"的判断，不是再一份数据导出。
- 第三方数据准确度有限，但客户接受这个局限性 — 提前对齐口径比假装精准更重要。
- 整条流程跑通后，可复用到其他客户、其他品类，只需替换数据源和品牌列表。
