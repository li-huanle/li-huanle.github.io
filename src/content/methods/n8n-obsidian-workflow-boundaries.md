## 解决什么问题

n8n 擅长“事件发生后调用什么”，Obsidian 擅长“人和 AI 如何长期阅读与维护知识”。如果让自动化直接改正式笔记，失败重试、重复写入和错误摘要会很快污染事实源。

## 职责划分

| 组件 | 负责 | 不负责 |
|---|---|---|
| n8n | 触发、连接 API、排队、重试、通知、状态流转 | 复杂业务判断、长期事实仲裁 |
| Obsidian | 可读事实、项目上下文、方法与决策、版本化维护 | 实时事件总线、高并发任务调度 |
| 脚本 | 确定性清洗、格式转换、结构校验 | 替代 AI 做语义判断 |
| LLM / Agent | 摘要、分类、对比、建议、异常解释 | 无证据写入正式事实、越权发布 |
| 人 | 目标、边界、验收、公开与停机判断 | 重复搬运和机械格式化 |

## 推荐链路

```text
Webhook / 定时器 / 表单
→ n8n 创建任务并记录唯一 ID
→ 脚本或 Agent 生成候选产物
→ 验证器检查结构、来源和状态
→ 人工确认高风险内容
→ 写入 Obsidian 收件箱或项目层
→ 读回确认成功
→ 更新任务状态
```

正式知识层不要成为自动化的默认写入点。自动产物先进入收件箱，经过合并、去重、冲突处理后再升级。

## 四个生产要求

1. **幂等**：同一任务重复执行不会生成多份内容。
2. **可恢复**：每个步骤有状态与错误信息，失败后从断点继续。
3. **有闸门**：发布、发送、删除、付款和正式事实写入保留人工确认。
4. **可观测**：知道输入、版本、耗时、输出位置和最终读回状态。

## 什么时候不需要 n8n

单机、低频、一步脚本能完成的任务，不必增加编排层。先用手工或 Skill 跑通 3 次，等输入输出和失败分支稳定，再考虑 n8n。自动化的目标是减少稳定流程的摩擦，不是把尚未想清楚的流程画成复杂节点图。

## 边界

- 凭证放在安全的密钥存储中，不写进工作流说明、日志或公开仓库。
- 外部 API、平台规则和节点版本属于时效信息，部署时必须重新核验。
- 涉及客户数据时遵守最小权限、最小留存与脱敏原则。
